# Verification and AI acceptance

Automated backend tests exercise actual authentication, ownership, CSRF, upload parsing, selected confirmation, correction/deletion invalidation, leases, outages, consent revocation and RAG source validation. They run with both isolated SQLite and a real separate MySQL verification database. Browser tests exercise the real HTTP upload/review/persistence/source/deletion flow and mobile layout. Vector verification uses the real persistent Qdrant engine. Synthetic accounts and provider fixtures exist only in test files.

`scripts/verify_ai_apis.py` checks live authenticated English/Tamil Laya decisions, hosted embeddings, Sarvam cited generation and Tamil translation using synthetic text. `--ocr-file PATH` explicitly sends the chosen PDF/image for document-extraction verification. Calls use provider credits. A successful smoke verifies integration, not medical routing accuracy. Laya probabilities use initial thresholds: route/support 0.6 and relevance 0.7. These are provisional settings and have not been calibrated on a representative clinical dataset.

Laya, Gemini and Sarvam keys are not supplied in the local configuration. All AI features must therefore be tested with real keys before relying on them. Automated HTTP adapter fixtures verify authentication, multilingual selection, Gemini query/document task types, embedding order/dimensions and normalization, malformed-output rejection and missing-key/outage behavior; these are protocol checks, not live-provider validation. The runtime reports unavailability; it never substitutes fabricated responses. API shapes were checked against the installed SDK and primary provider documentation.

Before wider use, collect consented or de-identified representative records and assess: OCR field precision, manually corrected values, selected versus unselected sources, English/Tamil routing, missing evidence, prompt injection in source/question text, stale vector hits, record changes during generation, unsupported diagnosis/treatment requests, citation correctness, numeric/unit/drug preservation in translation, latency, restarts and provider failures. Have a competent domain reviewer inspect the resulting answers. Track expected route/source/abstention and observed outcomes. Do not advertise accuracy percentages without measured results.

The deterministic validator is intentionally conservative and is not a complete medical safety classifier. Laya support checking adds a model decision and can still be wrong. The assistant provides informational explanations of reviewed records; diagnosis and treatment decisions remain outside the application scope.
